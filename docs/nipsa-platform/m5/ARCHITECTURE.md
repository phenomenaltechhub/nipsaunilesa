Threats: password guessing/enumeration/lockout DoS, concurrent-attempt bypass, session fixation/replay, CSRF/DNS rebinding, role/level IDOR, reset/MFA replay, student-data exposure, SQL/XSS, audit tampering, DB failures and destructive lifecycle operations. Strong hashing and per-account/network/global controls consume bounded resources; real shared-host memory/CPU/load limits still need measurement. Recovery uses an injected isolated test mail transport; no email is sent publicly. Production email, HTTPS, secrets management, offsite backups and MFA/recovery operational procedures remain launch blockers.

Verified-owner recovery remains a separate lane while the untrusted password lane is blocked; existing valid sessions survive unauthenticated guessing. Concurrent updates use transactions and recheck state after password verification. Production availability/DDoS resilience needs actual infrastructure, not a promise from local tests.
