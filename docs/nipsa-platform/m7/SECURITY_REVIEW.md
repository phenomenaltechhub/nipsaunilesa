# M7 security review and register

17 November 2026. Actual controlled HTTP/SQLite/Chromium tests and source/visual review are partial evidence, not certification or an independent penetration test. Production, real accounts/payments and paid infrastructure remain inactive.

## Trust boundaries and implemented controls

- **Student → examination:** deny by default; current session/active role/level/course/selected assignment/writer lease on every protected request. Server UTC deadlines, transactional attempt allocation, immutable encrypted approved question snapshots, strict answer schema, optimistic revisions, replay UUID/HMAC evidence and atomic finalization prevent client timing/score/attempt assertions.
- **Question bank → student:** admin-MFA review, strict MCQ/topic/source/difficulty/marks schema, bounded template imports, correction/withdrawal/version audit and schedule holds. Entry/assignment/attempt projections never include keys/explanations. Separate reviewed result publication; answer review embargo until the global window closes. Withholding revokes future result reads.
- **Mobile/browser → private storage:** private no-store JSON/modules/downloads, no private SW/localStorage cache, hidden/offline/logout/401/account-change clearing, late-render guards and explicit resume. In-memory unsent work cannot be guaranteed after disconnect/clear; acknowledged server state is authoritative. Memory clearing is not secure erasure or protection against a compromised device.
- **Representative → resources/notifications:** current scoped grants/MFA, independent publication, exact course/level/object checks, server-derived sender, duplicate/expiry/audience controls. Revoked publishers cannot activate future notices. Normal recipients cannot promote drafts or choose another student's records.
- **Upload → storage:** role/rate/body bounds before expensive work, actual UTF-8/PDF content checks, generated IDs/private encrypted storage, quotas/integrity and authorized attachment downloads. No arbitrary path storage. PDF/Office safety is not claimed without a real verified scanner; PDF absence/outage fails closed.
- **Member → community:** server current membership, open/closed/chat-only restrictions, persistence/order/replies/reactions/moderation/report ownership; stream synchronization never grants posting permission. One departmental room only.
- **Provider → payments:** server-owned references/amounts/currency/test domain, fixed HTTPS host/timeout/bounded response, raw signature check before parsing, transactionally idempotent event/order updates, refund/dispute holds and no client success proof. No automatic roster/account eligibility from callbacks/webhooks.
- **Account → lifecycle:** unchanged M5 scrypt/MFA/recovery/session/role policies, exact progressive lockouts and independent owner recovery. Local TLS tests verify certificates and Secure cookies; private key paths are bounded/regular/owner-only. Production mode remains refused.

## Confirmed integration findings corrected

1. Rapid answer selection and flagging could overwrite a pending answer with a stale closure value. Controls now merge against the latest pending/server state; the browser test introduces delayed writes and a dropped acknowledgement, then verifies retry/persistence.
2. Lost answer acknowledgements could produce a new request ID/stale-revision conflict. Retries now reuse the same queued write ID/body until acknowledged; server replay tests and actual browser response-loss testing execute the behavior.
3. Cleared offline/expired private workspaces lacked an h1. The privacy-preserving state now has a heading and account-access link; expired-session axe checks pass without exposing identity.
4. Dark-theme “Plan my study” inherited dark text on dark background (measured 1.54:1). The narrowly scoped selector restores white text. Real composited-image glyph/backdrop measurements supplement visual review at desktop/mobile light/dark. No CSP exception was added; the contrast helper loads a test-only intercepted same-origin stylesheet because inline injection was correctly blocked.
5. Adding batch fields exposed a positional M6 INSERT compatibility error during intermediate testing. The implementation now names columns explicitly; fresh/reopen/M6 upgrade and scheduling regressions verify the final schema. No old rows/history are reset.
6. Academic/answer review, live held/cancelled questions and result output are revalidated; private question/answer fields remain excluded before explicit permitted disclosure. Provider responses recheck current admin authorization after asynchronous work; upload scanning rechecks grants/revision before persistence.

## Standards reviewed

Use selected OWASP ASVS 5.0.0 controls and official Authorization, File Upload, CSRF, Session Management and Transaction Authorization guidance. Existing official ASVS/Authorization sources are the M6 review baseline; no certification is inferred. Relevant controls include V2.2.2 trusted validation, V3.3.4 cookie tokens, V3.5.7 authorized data separation, V5.2.4 bounded uploads, V8 function/object/field authorization, V15.4.2 atomic state changes and V16 security-event logging. Actual tests include IDOR/cross-level/replay/concurrency/session revocation, not assertions that a disabled button exists.
