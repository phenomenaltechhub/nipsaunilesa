# M8 Community contracts, privacy and maintenance

18 November 2026. This extends the **same controlled Node 24/SQLite account service**. It is not a second backend, a public deployment or production approval. Keep the existing loopback/synthetic-account/production-refusal boundaries, M5 sessions/recovery/MFA, M6 grants and M7 examination engine. See the [M7 contracts](../m7/API_AND_OPERATIONS.md).

## Authorization and API additions

All paths below have `/api/v1` prefix. Existing Origin/CSRF/session middleware and safe errors still apply. Every protected operation rechecks the current account. Administrator operations require the current administrator role and fresh MFA, rather than a client capability flag. A representative/executive title does not grant moderation.

## Images and storage

The browser accepts PNG/JPEG sources up to **1 MiB**, inspects dimensions before decoding (maximum 8,192 per dimension/16 megapixels), then converts/downsizes to PNG. The server independently validates actual PNG signatures, CRCs, chunk order, bounded inflate/scanlines, RGB/RGBA 8-bit nonanimated content, dimensions up to 2,048 per axis/4 megapixels, and **1 MiB canonical output**. Metadata/extra chunks/appended payload are not retained. SVG, GIF, WebP, documents and arbitrary files are unsupported. The base64 JSON body is separately bounded before expensive inspection.

Storage is encrypted inside the existing private database, with generated IDs, ownership checks before attachment, private no-store downloads and quotas of **10 MiB/member and 100 MiB total**. A member cannot attach another member's unused upload. Removed-message images are administrator-only. Unused uploads expire after one hour; normal group images/history are not given an unapproved global short timeout. Published-image retention and storage exhaustion require an approved operational policy before public use. This restricted native PNG canonicalizer is not a general-purpose malware-scanning service; the existing M7 PDF/Office blocker remains.

## Privacy and retention

- Normal group history remains persistent/searchable, paginated and capped at **300 rendered DOM messages**, not 300 stored messages. No new global group-message TTL.
- Read receipts reveal actual acknowledging IDs to the sender/authorized reviewer. Explain this to students. They cannot establish whether someone read attentively or prevent screenshots.
- Pending private requests expire after 24 hours without delivering private message content. Acceptance starts a separate **24-hour conversation lifetime**. Decline/block/close/expiry prevents further delivery. The five-second worker deletes inactive temporary payloads; terminal metadata remains up to seven days. A reported immutable snapshot follows moderation retention independently.
- Already accepted temporary conversations remain available during a **group-only** restriction, subject to their own consent/block/expiry and active-account/session checks. New requests require permission to post in the group. Account suspension/revocation still denies private access.
- Support records use **90 days after closure**, with open moderation holds. Resolving the final held report extends the support case for 90 days from resolution; it cannot vanish immediately because the original case was old. Resolved private report snapshots expire after 90 days. Open cases remain held. These implemented defaults still require institutional privacy/retention approval before real data.
- Database encryption is not end-to-end encryption. Server operators with authorized keys can decrypt. Logical deletion is not guaranteed erasure of SQLite pages, backups, screenshots or recipient copies. Encrypted backup custody, deletion replay after restore and production retention acceptance remain launch gates.
- Text drafts/retry IDs/reference selections may survive a disconnect in **short-lived same-account memory**, not localStorage or service-worker cache. Private DOM clears on offline/hidden/logout/expiry as before. Unsaved text/images are not guaranteed across a reload, process death or shared-device compromise. Only server acknowledgements mean saved.
- Audit events retain actor/action/target and permitted non-content metadata. Never log private bodies, report comments, image base64, cookies or credentials. Official **Admin** projections conceal the personal publisher from students while the actual administrator remains in the protected audit trail.

## Website content source and refresh

`npm run build` now builds Next.js, then indexes **actual exported public HTML title/description metadata** into `out/pharmaideia-content.json`. Private account/admin/PWA paths and individual executive profiles are excluded. It also lists existing Navigator records with explicit verification state and known record deep links. The current index contains **25 existing pages/records**; the two Navigator records are **candidates**, with **zero verified geographic markers**. A reference is not independent verification of an institutional facility.

`npm run references:snapshot` refreshes the bundled public-only fallback at `backend/public-data/website-content.json` from a successful current export. Review the diff: no student data, drafts, protected questions or invented slugs. `generatedAt` is indexing time, not publication time or source verification. The SHA-256 version detects content changes, not authorship/signature certification.

Students can use **+ → Website content**, type **`/website orientation`**, mention a unique complete auto-match title such as **Departmental Orientation**, or paste an exact known canonical URL. Search offers at most five real suggestions; a message may contain up to three references. Missing/ambiguous titles are not guessed. **Pharmly/Pharmily Hangout is absent and receives no fabricated URL.** Short/generic page titles require explicit selection. References store IDs/labels, never student-supplied URL/description metadata. Cards appear above the text; linked titles open the canonical HTTPS website with `noopener noreferrer`. Dismissal, corrections and replay are preserved. The shared component works in group chat, private/support messages and authorized notice publishing/corrections.

The backend has an optional **`PHARMAIDEIA_WEBSITE_FEED_REFRESH=1`** startup setting, default **off** until an approved public feed is actually deployed and reachable. Its sole destination is `https://nipsaunilesa.com.ng/pharmaideia-content.json`: five-minute conditional ETag pulls, five-second timeout, 1 MiB response limit, no redirects/cookies/student queries/body forwarding. Invalid/outage responses retain the last good index; a 403 blocks further retries for that process. Re-enable only after correcting configuration/access, then restart the controlled service. Do not repeatedly probe a blocked host.

A conditional 304 is accepted only after a validated response supplied an ETag; unsolicited 304 cannot mark the fallback live. Last-good feed/ETag are memory-only: restart loads the bundled snapshot, so restart/outage staleness remains an explicit launch-acceptance requirement.

When enabled and verified, a normal website publication/build updates the feed; the next successful pull changes suggestions/previews without a PWA redeploy. Active group messages resolve metadata changes/withdrawal through the live catalogue version; private notices/threads resolve on their existing poll. Browsers cache only public metadata in memory. Removed records show an unavailable card rather than inventing a new destination. This is index synchronization, not an Editorial integration or a real-time webhook claim.

**Current boundary:** production feed/website requests returned proxy CONNECT 403. Actual bounded refresh/ETag/change/withdrawal behavior passed controlled HTTP/browser tests, but no live feed deployment or external publication-to-PWA end-to-end was verified. The public website and Pages workflow were not deployed or reconfigured. Original standalone Editorial source is still unavailable. An eventual approved Editorial integration must publish the same public-only schema after editorial approval; do not scrape protected records or build a duplicate publishing system.
